The existing I2 read-only Go helper `evidence-services/cloud/cmd/research-i2-current-source/main.go` explicitly rejects any version except `telemetry-attestation-v1`. The existing Python `test/automation/integrity/i2_evidence.py` scorer also hard-codes v1, rejects `gateway_evidence`, and expects synthetic `i2-synthetic:` source keys. Therefore a PASS from its synthetic test is **not** a live I2 validation. The user-provided formal instruction to mutate one `temperature_c` value by +10 °C must not be applied to genuine v2 production rows with that v1 pipeline.

**Separate HRC exact-payload issue:** Current `internal/fabricadapter/worker.go` constructs the HRC source-bound anchor digest from the SHA-256 of the immutable, upstream `fabric_outbox.finalized_payload` BYTEA, rather than deriving the Fabric anchor digest from a newly generated `canonical_json`/JSONB projection. Post-storage tamper validation therefore needs to distinguish (1) immutable original exact-payload Fabric anchor digest, (2) original sealed evidence canonical digest/signature, and (3) a new **read-only** recomputation from potentially altered current source + its original independently verified gateway lineage. Equating those three digests or substituting a fabricated v1 snapshot would be a false security result.
