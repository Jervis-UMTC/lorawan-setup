## Revised screenshot standard

1. Capture must be NON-INVASIVE: use an isolated headless browser context or already available saved original screenshots. Do not open, raise, resize, focus, type into or switch tabs in the user's ordinary desktop browser; do not use desktop SendKeys or foreground window capture. Never touch the user's current window/session. If an authorized headless session is unavailable, label the screenshot as pending rather than disrupt the user.
2. For any long page/form use a real full-page capture including every field down to Submit, from the authorized project UI; pair with a genuine non-invasive browser viewport only if useful for location/navigation. Do not crop away relevant buttons, columns, control states or status, distort the aspect ratio or present a partial viewport as the complete page. The older desktop Firefox scripts are retained only as capture provenance and MUST NOT be rerun in a user-facing desktop session.
3. A full-page screenshot too tall to read at Word size must be split into labeled, readable top/bottom sections **from the real original**, without omitting intermediate controls. The complete original remains in `assets/` and can be used for traceability.
4. Put each screenshot right beside the numbered action it explains and give an action caption; avoid date/workstation metadata in the manual. Treat architecture/vendor diagrams as references, never test-result evidence.
5. No password, AppKey/NwkKey, private key, token, sensitive serial log or arbitrary new gateway/device registration in captured images. Historical readings are not newly measured research results.
6. Validate the DOCX and visually render *every page* before publishing.
