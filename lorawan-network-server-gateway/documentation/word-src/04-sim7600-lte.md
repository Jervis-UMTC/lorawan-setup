# Chapter 4 — Set Up the SIM7600 LTE Internet Connection

## 4.1 What the SIM7600 does

**Gateway-01 receives sensor signals through RAK5146, then sends the resulting MQTT packets to the cloud through its separate Waveshare SIM7600G-H 4G USB dongle.** LoRaWAN and LTE are different radios. The RJ45 Ethernet cable provides local gateway administration; it must **not** accidentally replace LTE as the Internet path during a research test.

Our commissioned path is:

**Gateway-01 local Mosquitto → SIM7600 QMI → `wwan0` → DITO LTE → `smartagri-mqtt.duckdns.org:8883` → two cloud MQTT bridge connections.**

When LTE disappears, the gateway's local persistent MQTT buffer and independent evidence journal retain pending traffic. The managed LTE controller later reconnects the modem and resumes delivery.

## 4.2 Insert the SIM, attach the correct antenna and plug in the dongle

**Do these steps with Raspberry Pi power disconnected if you are assembling or changing the modem.**

1. Find the **Waveshare SIM7600G-H 4G DONGLE**, the small black USB device shown below, **not** a second Raspberry Pi HAT. Its casing has **USB**, **ANT**, and **PWR/STA/NET** markings.
2. Check that the DITO **nano-SIM** has an active cellular-data plan. On the dongle, open the SIM-slot cover, unlock the internal holder in the direction marked **OPEN**, place the nano-SIM according to the printed orientation, relock to **LOCK**, and close the cover. **Do not force the holder or cut a larger SIM by hand.**
3. Attach the supplied **LTE antenna** to the dongle's connector labelled **ANT** and point it upright, away from metal enclosure walls. This is **not** the gateway RAK5146 LoRa connector labelled LoRa and not its GNSS port.
4. Plug the dongle directly into the commissioned Raspberry Pi USB connection (or the verified supplied USB extension cable). Avoid a passive, unpowered USB hub. Keep the gateway's Ethernet management cable connected if you need SSH.
5. Power Gateway-01. Let the modem register to the carrier; do not assume a particular LED blink alone proves data or MQTT connectivity.

## 4.3 Check that Gateway OS recognizes the modem

In **Windows PowerShell** connect to Gateway-01: `ssh root@192.168.20.11`. Run the following block **inside Gateway-01's OpenWrt BusyBox terminal**:

```sh
echo '=== SIM7600 USB ==='
lsusb 2>/dev/null || true
echo '=== QMI AND SERIAL DEVICE NODES ==='
ls -l /dev/cdc-wdm* /dev/ttyUSB* 2>/dev/null || true
echo '=== LTE DATA INTERFACE ==='
ip link show wwan0 2>/dev/null || true
echo '=== RECENT MODEM DRIVER LINES ==='
dmesg | grep -Ei 'simcom|sim7600|qmi|cdc-wdm|wwan|usb' | tail -n 35
```

**PASS:** SIMCom USB detected, `/dev/cdc-wdm0` exists and network device `wwan0` exists. A commissioned SIM7600 AT control port historically appeared as `/dev/ttyUSB2` (do not hard-code other numbered `ttyUSB` nodes). An intermittent USB device or missing `cdc-wdm0` is **power/USB/driver first**, not APN or ChirpStack.

The approved custom Gateway OS image already includes the matching USB-serial/QMI drivers. **Do not install random stock OpenWrt kernel modules or change the modem USB composition** just because an online SIM7600 tutorial uses PPP, RNDIS or an AT dial command.

## 4.4 Check the exact QMI interface settings

1. In Gateway-01's browser `http://192.168.20.11/`, open **Network → Interfaces → lte**.
2. Read the interface configuration and compare it to Figure 4.2 below. On a **working commissioned gateway, inspect only**; do not overwrite a healthy connection. If you are intentionally provisioning a new approved card, enter the settings from the worksheet.
3. Set the APN for the **commissioned DITO SIM** to `internet.dito.ph`. Use **QMI Cellular**, control device `/dev/cdc-wdm0`, authentication **none** and the commissioned effective UCI `pdptype=IP`. The live LuCI dropdown can display `IPv4/IPv6`; do not change a working modem simply because the displayed label differs from the underlying UCI value. Do not substitute a foreign-carrier APN.
4. The project's route controller requires **netifd default route OFF**, **peer DNS ON**, and **automatic lte_4 DHCP child OFF**. It installs the LTE Internet route itself. Use Save & Apply **once** only when you actually changed an approved configuration; allow reconnection.

**Exact tracked configuration, for an authorized initial build or replacement—not a health-check command:**

| OpenWrt setting | Approved commissioned value |
|---|---|
| Logical interface / protocol | `lte` / `qmi` |
| QMI device / resulting data interface | `/dev/cdc-wdm0` / `wwan0` |
| Carrier and APN | DITO / `internet.dito.ph` |
| Auth / PDP | `none` / `IP` |
| DHCP child / netifd default route | `0` / `0` |
| Carrier-provided DNS | `peerdns=1` |
| Health-managed production default | `wwan0`, normally metric **10** |
| Management Ethernet | `br-lan`, `192.168.20.11/24`; **never** production default |

**Gateway-01 BusyBox — read-only setting check:**

```sh
echo '=== COMMISSIONED LTE UCI ==='
for k in proto device apn auth pdptype dhcp defaultroute peerdns; do
  printf '%s=' "$k"
  uci -q get "network.lte.$k"
done
```

**PASS:** `qmi`, `/dev/cdc-wdm0`, `internet.dito.ph`, `none`, `IP`, `0`, `0`, `1` in that order. A blank/mismatched value means inspect the actual deployed configuration and SIM before changing anything.

## 4.5 Confirm LTE really carries cloud traffic

A green modem or `connected` status **does not prove Internet traffic works**. Gateway-01's `/usr/sbin/lte-route-health` installs a health-managed LTE default, probes the IP dataplane and tests MQTT mTLS separately. Management Ethernet must remain available without becoming an Internet shortcut.

**Gateway-01 BusyBox — read-only check:**

```sh
echo '=== LOGICAL LTE SESSION ==='
ubus call network.interface.lte status
echo '=== CURRENT CELLULAR ADDRESS ==='
ip -4 addr show dev wwan0
echo '=== DEFAULT INTERNET ROUTE ==='
ip route show default
echo '=== ROUTE TO COMMISSIONED CLOUD IP ==='
ip route get 129.212.208.168
echo '=== CLOUD DNS ==='
nslookup smartagri-mqtt.duckdns.org
echo '=== TLS CLOCK ==='
date -u
echo '=== AUTOMATIC LTE CONTROLLER ==='
logread | grep 'lte-route-health' | tail -n 18
```

**PASS:** a current, carrier-assigned LTE IPv4 address; preferred default via **`wwan0` metric 10**; broker route via `wwan0`; cloud DNS resolves; UTC is usable for certificates; log reports **LTE dataplane PASS**. The historical cloud address `129.212.208.168` is not a guarantee that DNS can never change; check the active bridge hostname and resolved address whenever the broker is migrated.

## 4.6 Confirm the cloud MQTT bridge is actually connected over LTE

The LTE route itself does **not** prove the gateway reached ChirpStack. The two commissioned Mosquitto cloud bridges should have **established TLS connections** on port **8883**.

**Gateway-01 BusyBox — do not print certificates/private-key content:**

```sh
grep -E '^(connection |address |remote_clientid|bridge_cafile|bridge_certfile|bridge_keyfile|bridge_insecure|topic )' /etc/mosquitto/conf.d/bridge.conf 2>/dev/null || true
ss -tn 2>/dev/null | grep ':8883' || netstat -tn 2>/dev/null | grep ':8883' || true
logread | grep -Ei 'mosquitto|bridge|connack|tls' | tail -n 25
```

**PASS:** two intended cloud MQTT TCP sessions in `ESTABLISHED` state; they use the configured broker host on port `8883` and the route to the broker uses LTE. A socket or TLS success alone does not certify a real sensor uplink. You do **not** need to create an extra test MQTT client just to observe the existing bridges.

## 4.7 When mobile data disconnects

**This is the expected recoverable behavior:**

1. RAK5146 continues receiving permitted LoRaWAN frames when the sensor remains powered.
2. The **loopback Mosquitto** buffer retains QoS-1 uplinks while the cloud bridge is unreachable.
3. The independent gateway journal retains source lineage; do not delete these files to clear an error panel.
4. The LTE controller checks approximately every **30 seconds**, allows a short boot grace and performs staged reconnect only for a **failed cellular IP dataplane**, not merely a distant MQTT server outage.
5. When the carrier reconnects, MQTT bridge sessions re-establish and retained uplinks drain.

**Never:** erase `mosquitto.db`, delete the gateway journal, hard-code a management Ethernet Internet route, randomly restart all gateway services or send `AT+CUSBPIDSWITCH` / `AT+CFUN=1,1` as a routine test. Preserve management access and the research recorder's active count.

If the modem is absent, solve power/USB first. If modem and IP are healthy but MQTT is down, inspect DNS/UTC/TLS/broker before resetting LTE. Only use the documented bounded recovery during a genuine diagnosed outage and outside a counted test.

## 4.8 Quick fault guide

| Observation | First check |
|---|---|
| No SIMCom device | Power, USB plug/extension, dongle, SIM seating |
| USB exists, no `/dev/cdc-wdm0` or `wwan0` | Custom Gateway OS QMI drivers and USB stability |
| `wwan0` exists, no carrier session | DITO SIM/data plan, antenna, `internet.dito.ph`, signal |
| Carrier session says connected but Internet fails | Real IP dataplane; `lte-route-health` log, avoid false PASS |
| Internet works but cloud DNS/TLS fails | Resolver, UTC, cert/hostname and broker endpoint |
| Cloud MQTT connected, no incoming sensors | Go back to Chapter 3 RF/Concentratord then ChirpStack |
| LTE outage, buffer grows | Keep queue/journal; restore carrier rather than deleting evidence |
