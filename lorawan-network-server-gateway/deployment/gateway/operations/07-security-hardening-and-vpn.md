# ChirpStack Gateway OS Security Hardening and VPN

Use this guide to secure the gateway management interfaces, enforce minimal service surface, manage mTLS identities, configure firewall boundaries, and maintain security lifecycle procedures.

---

## 1. Management access

- Change the default root password immediately post-commissioning.
- Disable the commissioning Wi-Fi Access Point (AP) after initial configuration.
- Restrict LuCI Web GUI and SSH access strictly to loopback, management LAN, or a VPN tunnel (WireGuard / OpenVPN).
- Do not expose gateway management ports (`22`, `80`, `443`) to the public WAN/cellular interface.
- Ensure NTP time synchronization is active; accurate system clocks are required for mTLS certificate validation.

---

## 2. Minimal service surface

Enable only the reviewed, required services:

```text
Concentratord
MQTT Forwarder
local Mosquitto (bound strictly to 127.0.0.1:1883)
reviewed integrity journal
reviewed journal checkpoint/segment uploader
required OpenWrt networking and supervision services
```

> [!WARNING]
> Keep UDP Forwarder disabled. Do not install Gateway OS Full, LoRa Basics Station, Docker, a local ChirpStack server, or another packet forwarder on the gateway.

The software integrity journal consumes the supported Concentratord event interface read-only. Assign it a dedicated service identity and write permissions only to its isolated evidence directory (`/var/spool/gateway-journal/`); MQTT Forwarder and Mosquitto must not have write permissions to evidence directories.

---

## 3. MQTT credential isolation & PKI

Each gateway receives a unique client certificate and private key pair generated by the root CA:

- **Client Certificate CN**: Set to the 16-hexadecimal `<GATEWAY_EUI>`.
- **Private Key Storage**: Saved as `/etc/mosquitto/certs/<GATEWAY_EUI>.key`, owned by `mosquitto:mosquitto`, mode `0600`. A server-staging copy may be `root:root 0600`; the active gateway copy must be readable by Mosquitto.
- **Root CA Key**: Never copy the Certificate Authority (CA) private key (`ca.key`) onto the physical gateway.

---

## 4. Certificate lifecycle and revocation

Maintain a record of:
- Certificate serial number and SHA-256 fingerprint;
- Expiration date and automated renewal schedule (at least 30 days prior to expiry);
- Encrypted offline backup location of gateway credentials;
- Emergency revocation protocol in case of physical gateway theft or SD card compromise.

Test client-certificate rejection using an expired or revoked certificate in staging to verify that the remote broker denies unauthenticated bridges.

---

## 5. Cellular 4G backhaul and firewall isolation

The gateway operates strictly via **outbound connections** (initiating mTLS to the server broker on port `8883`).

- **Inbound Firewall**: Set default WAN input policy to `REJECT` or `DROP`.
- **No Port Forwarding**: Do not enable carrier NAT port forwarding or dynamic DNS for inbound access.
- **VPN Backhaul**: When remote SSH access is required over 4G/cellular links, establish an outbound WireGuard or OpenVPN tunnel to a central management server.

---

## 6. System backups and upgrade safety

Before performing any Gateway OS or software upgrade:
1. Generate a static configuration archive using `sysupgrade -b /tmp/gw-<GATEWAY_EUI>-backup.tar.gz`.
2. Save a copy of the active `uci` state (`uci show chirpstack-concentratord`, `uci show chirpstack-mqtt-forwarder`).
3. Store the backup off-device on an encrypted management server.
4. Verify the factory Gateway OS Base image digest before flashing.

---

## 7. Security acceptance criteria

- Management interfaces (SSH/LuCI) are restricted and unexposed to public WAN.
- Default credentials removed and Wi-Fi commissioning AP disabled.
- RAK5146 regional frequency plan matches regulatory standards.
- Local Mosquitto broker listens exclusively on `127.0.0.1:1883`.
- Outbound bridge authenticates via mTLS with unique `<GATEWAY_EUI>` CN.
- Cross-gateway ACL denial verified (Gateway A cannot publish to Gateway B topics).
- UDP Forwarder is completely disabled.
- Software integrity journal sequence and hash continuity pass verification.
